# HMall 五个微服务代码练习

这份题库用于熟悉一个已有项目：先读清楚一段代码负责的功能，再根据中文步骤补全关键代码，最后对照答案解释自己的选择。

第一版是 **12 道样例题**，用于确认练习形式。入口是 [第一组：题目与答案](01-five-services.md)。题目在前，完整参考答案集中在文档后半部分。

## 五个服务分别负责什么

| 服务 | 主要工作 | 第一版对应题目 |
| --- | --- | --- |
| `cart-service` | 维护用户购物车，查询时补充商品最新信息 | Q01、Q02 |
| `item-service` | 商品增删改查、分页、库存扣减 | Q03、Q04、Q06 |
| `user-service` | 登录、校验密码、生成登录令牌 | Q05 |
| `trade-service` | 维护业务订单，处理支付成功后的订单状态 | Q07 |
| `pay-service` | 管理支付单，将支付成功事件写入 Outbox | Q08 |

Q09、Q10 练习这些服务使用的公共组件和配置。Q11、Q12 从仓库中的 `lottery-service` 补充 Redis 和 Redisson 练习；它们不是上述五个服务已有的购物车缓存功能。

## 先练哪一题

先做 **Q01：查看我的购物车**。它完整展示了本题库的主要形式：功能说明 → 真实文件路径 → 现有上下文 → 分步骤填空 → 自查场景 → 文档后面的答案。

推荐顺序：Q01 → Q02 → Q03 → Q04 → Q05 → Q06 → Q07 → Q08 → Q09 → Q10 → Q11 → Q12。前五题偏基础，后面逐步涉及并发、事务、配置和 Redis。

## 怎么填写

1. 打开题目，先读“该部分是完成什么工作”和“已提供的上下文”。
2. 在文档的代码块中替换 `__Q01_01__` 这样的占位符，或者把代码复制到自己的练习副本中填写。占位符前面的中文注释就是步骤提示。
3. 一个占位符可能代表一个表达式、一条语句或一段注解。题目已经写好的括号、引号、分号需要保留。
4. 填完后先用“自查场景”检查思路，再打开对应答案。写法可以不同，但查询范围、返回结果、状态约束等行为要一致。
5. 对照原文件继续看调用关系，练习用自己的话说明为什么要这样写。

这些练习代码是从现有类中抽取的方法或配置片段，**不是独立可运行的 Java 项目**。题目会列出类成员、辅助方法和导入来源。想在 IDE 中运行时，应在练习副本中保留原类的包名、导入、继承关系和其余方法，再替换题目对应片段。

题库放在 `docs/practice`，不参与 Maven 编译。业务源码没有为练习改成填空版本。

## 一个题目固定包含什么

```text
题号：Qxx
题目：完成某个具体业务功能

该部分是完成 XXX 工作的。
原文件路径：具体的 Controller / Service / Mapper / YAML 文件
定位：方法名或配置节点
主题组件：它负责什么，为什么这个功能需要它
代码范围：完整方法 / 多个方法 / 配置片段 / 教学改写
已提供的上下文：已存在的类、成员、辅助方法、相关导入

练习代码：
1. 中文注释，说明这一小步要完成什么
   留出代码填写位置
2. 中文注释，说明下一步要完成什么
   留出代码填写位置

自查场景：输入、预期结果、需要考虑的边界
参考答案：在所有题目之后，给出完整代码和原因解释
```

## 组件与练习主题对照

| 组件或机制 | 这份题库里的主题功能 |
| --- | --- |
| MyBatis-Plus | 简化数据库增删改查，将分页结果转换成接口返回值 |
| OpenFeign + Nacos | 按服务名调用商品服务；Nacos 提供注册发现和外部配置 |
| BCrypt + JWT | 校验密码摘要，生成带有效期的登录令牌 |
| MySQL 条件 UPDATE | 让“库存足够”和“扣库存”在一条 SQL 中执行，处理并发扣减 |
| MySQL `FOR UPDATE` | 在数据库事务中锁住订单记录，协调重复支付回调 |
| Spring 事务 + Seata AT | 管理本地数据库事务，以及接入同一 XID 的跨服务数据库事务 |
| Outbox + RabbitMQ | 先在业务事务中保存待发送事件，再由现有 relay 投递消息 |
| `@ConfigurationProperties` | 把 YAML 配置绑定成 Java 对象，供业务类使用 |
| Redis + Lua | 原子处理抽奖次数检查、预占和重复请求 |
| Redisson `RLock` | 按活动和用户协调多个服务实例的抽奖操作 |

第一版聚焦这些机制在当前项目中的实际用途，没有覆盖每个服务的所有功能。
