## 未决事项与迁移门槛

- 仅当现存账号已由数据库负责人确认只有 `SELECT` 权限、MySQL 客户端可用，并且 `luckyhub`、`hm_item`、`information_schema` 均可读时，才可执行 `scripts/migration/marketing-points-preflight.sql`。不得创建/修改账号，不得使用权限未知的应用账号，也不得启动 Compose、schema 初始化或其他状态化服务来满足条件。
- 本预检仅检查积分数据对 `luckyhub.sys_user` 的引用存在性，不证明 Marketing 用户 ID 与 `hm_user.user.id` 的身份对应关系。独立身份/RBAC 审计仍未运行，是所有基于用户 ID 的迁移硬门槛。
- 任何账户/流水/兑换用户孤立引用、重复幂等键、余额快照不一致、冲正关系异常、订单来源/金额/商品引用异常或履约快照不一致，都只记录脱敏聚合并暂停对应积分迁移。不得自动修改 ID、合并账号、补流水、改余额、恢复 offer 库存或复制权限。
- 总设计目标由 `points-service` 管理账户、不可变流水、运营调整、冲正和兑换；实物信息/真实库存归 item-service，实物兑换履约归 fulfillment-service。现有 Marketing 积分兑换实现直接跨目录/库存/地址快照/物流单写操作。其拆分后的跨服务事务、额度预留、事件幂等、失败补偿及同步响应语义必须另行设计并验收，不能从本预检推断已解决。
- 本报告和 SQL 合同测试只是审计准备，不代表数据库连接、SQL 执行、积分数据核对或 `points-service` 创建/迁移已经完成。
